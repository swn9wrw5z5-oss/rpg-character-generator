## 已確認的計算契約

以下是 V5 現行試算公式；有公式不代表參數已正式定案。

1. 種族：15 列目前全部啟用、權重皆 10。若照全啟用池抽取，每種機率為 1/15；S009–S013 五列仍標示「造型占位，未定種族」，必須顯示此狀態，不能包裝成正式種族。
2. 背包：依該種族最小／最大寬高與全域上限 10×8 驗證；必須是正整數。分數 `max(0, 寬×高 − 免費格數) × 每格成本 × 背包倍率`。現值免費35格、每格2、倍率1.1111111111111112；80格為100分。操作區完全獨立，不產生尺寸、不扣預算、不計分。
3. 初始能力分：四項各自 `(初始值 − 初始計分零點) / 每分提升量` 後相加，不先取整。HP 每分5、MP每分3、HP回復每分2、MP回復每分0.2；計分零點皆0。
4. 能力上下限：HP 5–100、MP 3–48、HP回復0.5–20、MP回復0.2–10。初始基準100／30／0／0，其中兩項回復基準低於最小值；不能直接全部採基準生成，也不能暗自修改來源。
5. 成長：四項評級獨立保存；各評級成本 D=0、C=5、B=10、A=15、S=20。四項成本相加為隱藏潛力分，現表最高80分。每級成長對應各能力欄位，並非初始值的百分比。
6. 技能詞綴分：`角色計算!B13` 將 B21:B25 的技能取得成本相加。目前每項連結 `計分參數!B11`，為30分草案；五格只是範例上限，不是正式抽取數量規則。可供生成僅 K001–K009；不得因其他技能也有成本欄就將其啟用。
7. 實際總分：`背包分 + 基礎能力分 + 技能詞綴分 + 隱藏潛力分`。剩餘預算=`分配預算 − 實際總分`。取得成本已計為擁有價值，不能再從總價值扣除；施放消耗與取得成本不同。
8. 稀有度：保留總分小數，使用 `floor(總分)` 查啟用區間且恰好命中一個。普通0–119、稀有120–199、史詩200–299、傳說300–399、神話400–999999。119.999仍普通，120才稀有。區間外、重疊均應錯誤，不任意補分類；絕不抽稀有度或讀取 C 欄舊權重。
9. 培養公式：`初始值 + max(0, 等級−1) × 該能力評級每級成長 × (1 + 全部隱藏潛力分 × 隱藏每分成長增幅)`。現增幅0.01，因此任一能力的評級成本會影響所有能力的成長倍率，必須照實標示。這是試算預設，並非四項完全互不影響。`成長成本每級倍率` B15 未被現行角色公式使用，不自行套用。

## 資料問題與限制

自動稽核回報10項（見 `evidence/validation-results.json`）：

- 四項缺少引用：TAL_TOUGH／TAL_MANA／TAL_COUNTER／TAL_PACK 分別引用不存在的 SKILL_TOUGH／SKILL_MANA／SKILL_COUNTER／SKILL_PACK。即使啟用欄為1，也必須排除有效生成池並顯示原因。
- S006 規則 VIS_006 仍 F02／QUADRUPED，種族設定已為 F01／HUMANOID；BODY_HUM_01 是共用引用但素材列只標S001，需確認共用語意，不可自動判定不存在。
- S014、S015 各自缺少外觀規則，且 BODY_BEAST_05 屬 F02／S006／QUADRUPED，與兩種族的F03／HUMANOID不一致。先以文字展示種族，不能冒用正式圖片或偷偷換素材。

其他人工檢閱發現：

- TAL_TRANSFORM、TAL_CONTRACT 有有效技能引用，但仍為草案；形態／召喚物只有範例 ID，沒有可抽取目標資料或實際效果。允許測試展示時須標「綁定目標未定／效果未實作」，不能把例子當每個角色相同的正式綁定。
- 技能施放 HP、MP、物品數為0且消耗組合為待設定；不表示已確認免費。模擬器只做生成與估值，不能聲稱技能戰鬥效果已實作。
- 個性玩法效果ID皆空；備註提及攻擊、包包偏好等文字沒有數值公式，不可直接改變能力、背包或權重。
- 使用說明仍說13款造型（1／5／1／1／5），族系表造型規劃數卻為3／5／5／3／5（合計21）；種族列另有15列。三者用途與數量不一致，不能互相推定。
- `玩家顯示!B9` 要求不匯出成長評級，與使用者要求首頁顯示四項評級不同。遵循本次使用者需求：玩家顯示評級，隱藏成本、總分、預算與成長公式只在開發者模式。
- 純 GitHub Pages 網頁可隱藏畫面資訊，但使用者可查看下載的 JSON／JS；兩模式是展示分流，無法提供真正機密隔離。需要真正秘密資料時須另建伺服器，非本次靜態工具的能力。
- `角色計算!B18` 內層仍要求第一技能欄 B21 存在：外層雖允許空，全部無技能會被拒絕。這與「可選零技能」測試方案不一致；先記錄，不修改原 Excel。
- 公式大量使用固定列範圍（技能至37、種族至16、成長至6）；新增 Excel 列後不能只依舊公式快取，正式匯出器必須依主鍵有效列掃描並檢查公式支援範圍。

## 匯出與驗證設計

本階段的 `inspect-v5.ps1` 是唯讀稽核工具，輸出帶儲存格座標的 JSON 證據，**不是可供網頁直接使用的正式轉檔器**。不執行 Excel 巨集、外部連結或文件內指令，也不以 V4 歷史表回補值。共享公式保留原始 XML 屬性，未展開／執行，不能把空公式從屬格視為已重算。

後續正式流程：編輯 V5 → Excel 重算並儲存 → 轉檔工具依欄名與 ID 產生版本化設定 JSON → 驗證通過才發布 → 靜態網頁載入 JSON。衍生成本須依參數重算或使用驗證過的公式，不依賴可能過期的快取；遇到未支援公式應明確失敗。原始備註與狀態欄必須保留，以供開發者提示。

正式驗證門檻：必要工作表／欄位與型別、缺少／重複主鍵、權重為有限非負數且有效池總權重大於0、正整數尺寸及上下限、零／負每分提升量、能力邊界、合法評級、各關聯與綁定目標存在性、候選狀態隔離、稀有度整數區間合法／無重疊／無缺口、預算可行性、圖片不存在時文字占位。警告不能當成通過；已知無效天賦可保留在候選資料區，但不得流入可生成集合。
